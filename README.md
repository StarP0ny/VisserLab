# VisserLab

Регистратор опытов: приборы подключаются как плагины, запись идёт в папку опыта, журнал ведётся рядом с данными, управление через веб-интерфейс с ПК или телефона.

Сейчас работает регистратор платы Pt100 из командной строки. Интерфейс пока существует как макет: [docs/mockup.html](docs/mockup.html).

## Запуск

```
pip install -r requirements.txt
python -m visserlab record --name dry01 --note "пустой патрон"
python -m visserlab record --duration 60
python -m visserlab probe scan
python -m visserlab probe dump --addr 1
```

Во время записи: Enter ставит метку, текст + Enter — заметку, `q` — стоп.

Что к чему подключено, описывает [visserlab/stand.yaml](visserlab/stand.yaml).

## Опыт на диске

```
runs/<YYYY-MM-DD_HHMMSS>_<имя>/
  meta.yaml      снимок stand.yaml, время, заметка, коммит кода
  events.jsonl   журнал: метки оператора и системные события
  <прибор>.csv   свой файл у каждого прибора, общая шкала t_unix
```

В файлы пишется то, что отдал прибор. Калибровки и привязка «канал → точка» хранятся в meta.yaml и применяются при анализе.

## Приборы

| Прибор | Подключение | Статус |
|---|---|---|
| PTA8D08, 8 × Pt100 | Modbus RTU, RS485 | работает. Регистры 0–7 — °C×10, 32–39 — Ом×10 |
| Victor 328B, тепловизор | USB UVC | нужно проверить, отдаёт ли он UVC |
| SCD41, SHT45, SDP810, O₂ | через МК-шлюз | протокол шлюза ещё не продуман |

## Решения по интерфейсу

- Окно 0: новый опыт или анализ. Если опыт идёт, по центру плашка с кнопкой перехода к нему. Опыт всегда один.
- Шаг 1 — выбор приборов (плитки или список). Автопоиск проверяет каждый прибор на параметрах драйвера по умолчанию. Недоступные приборы скрыты.
- Шаг 1.1 — настройки. Форма генерируется из схемы драйвера, шаг можно пропустить.
- Состояния: подготовка → запись ⇄ пауза → стоп. Стоп возможен только из паузы, на паузе запись продолжается.
- Состояние опыта показывает значок: зелёный — норма, жёлтый — нужно внимание, красный — ошибка.
- На поле панелей перетаскивается визуализация канала. Брошенная на занятую панель, она накладывается: не больше двух единиц измерения на панель. С Alt (на телефоне — долгое нажатие) переносится прибор целиком, по одной панели на единицу измерения.
- Ширина панели: 1 → 2 → вся строка. Панель можно вынести в отдельное окно браузера.
- Журнал: время заметки берётся по первому нажатию клавиши. Изменения настроек записываются как «было → стало».
- Точки замера на кадре тепловизора становятся каналами.
- Приборы за МК-шлюзом при потере связи получают одну общую ошибку.
- Тексты в интерфейсе короткие, пояснения — во всплывающих подсказках.
- Разбор завершённых опытов открывается отдельным окном и продумывается отдельно.

## План

1. Ядро сборщика. Интерфейс драйвера: схема настроек, типизированные каналы, поиск. Сборщик работает отдельным процессом, команды получает через stdin, отдаёт поток JSON. Pt100 становится первым драйвером.
2. FastAPI + WebSocket. Окно 0 и панель опыта на живой плате Pt100.
3. Драйвер тепловизора: кадр, профиль, точки замера.
4. Выбор приборов, настройки, окно прибора, раскладка на Dockview, пульт для телефона.
5. Протокол МК-шлюза.
