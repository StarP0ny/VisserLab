# VisserLab

Регистратор опытов. Приборы подключаются как плагины, запись идёт в папку опыта, журнал ведётся рядом с данными, управлять можно с ПК или с телефона.

Готовы **сборщик** (приборы, запись, предзапись, журнал, оповещения) и **веб-интерфейс**: окно 0, выбор и настройка приборов, панель опыта с графиками, кадром тепловизора, журналом и раскладкой для телефона. Одобренный макет: [docs/mockup.html](docs/mockup.html).

## Установка

```
pip install -e ".[dev]"
```

## Запуск

Два окна консоли:

```
python -m visserlab collect          # сборщик: держит приборы и пишет опыты; Ctrl-C — стоп с сохранением
python -m visserlab web              # веб: http://127.0.0.1:8080/
```

Веб открыт и для телефона: ссылку с токеном он печатает при запуске, а кнопка «Телефон» показывает её QR-кодом. Без токена с другого устройства не пустит. Токен хранится в `config/web_token` и переживает перезапуск; `--new-token` выдаёт новый, `--host 127.0.0.1` закрывает веб от сети. Windows при первом запуске спросит про брандмауэр: разрешите для частной сети. Если сборщик не запущен, веб это покажет, но сам его не запустит.

Без стенда запустите сборщик на симуляторах: `python -m visserlab --config tests/stand collect`. Там Pt100, тепловизор, МК-шлюз с SCD41 / SHT45 / SDP810, шприц, вычисляемая влажность и Pt100 «на шине» со сбитыми адресом и скоростью: его находит перебор. Шаблон `sim` ускоряет время в 10 раз. В основном конфиге симуляторов нет.

Консоль вместо веба:

```
python -m visserlab devices                                  # кто из приборов отвечает
python -m visserlab ctl prepare name=dry03 template=visser_patron
python -m visserlab ctl start | note текст | pause | stop | watch
python -m visserlab ctl scan [devices=pt100] [port=COM27]    # перебор скорости и адреса
python -m visserlab record --template visser_patron          # без сборщика: запись прямо из консоли
```

## Устройство

```
config/devices.yaml        приборы стенда: драйвер, настройки, подписи каналов, дети шлюзов
config/local.yaml          найденное перебором на этом ПК; перекрывает devices.yaml, не в git
config/web_token           токен ссылки для телефона, не в git
config/templates/*.yaml    шаблоны опытов: приборы, настройки, правила оповещений, раскладка
visserlab/core/            ядро: контракт драйвера, сборщик, запись, буферы, оповещения, TCP-сервер
visserlab/drivers/         pta8d08 (Pt100), uvc_thermal (тепловизор), manual, calc
visserlab/web/             мост WebSocket ⇄ сборщик и статика интерфейса
docs/COLLECTOR.md          протокол, состояния, формат опыта на диске
tests/                     ядро, перебор и веб: python -m pytest
tests/stand/               стенд из симуляторов: конфиг и драйверы (plugins в devices.yaml)
```

## Приборы

| Прибор | Подключение | Статус |
|---|---|---|
| PTA8D08, 8 × Pt100 | Modbus RTU, RS485 | работает, перебор находит плату за секунду. Регистры 0–7 — °C×10, 32–39 — Ом×10, 0xFD — адрес, 0xFE — код скорости |
| Victor 328B, тепловизор | USB UVC (MSMF) | работает: кадр 256×192 с температурой, профиль, зоны из настроек, точки по клику. Запись 1 / 5 / 25 к/с, кадр — среднее за интервал. Подробности — в [uvc_thermal.py](visserlab/drivers/uvc_thermal.py) |
| SCD41, SHT45, SDP810, O₂ | через МК-шлюз | протокол шлюза ещё не продуман; есть симуляторы в tests/stand |
| Шприц-проба, весы | ручной ввод | работает |

## Решения по интерфейсу

- Окно 0: новый опыт или анализ. Если опыт идёт, по центру висит плашка с переходом к нему. Опыт всегда один.
- Шаг 1: выбор приборов, плитками или списком, недоступные скрыты.
  - «Обновить» — одна проверка каждого прибора на текущих настройках, с правками из ⚙.
  - «Поиск» — перебор скорости и адреса у всех ненайденных. У ненайденного прибора есть «Перебор»: только он, порт выбирается.
  - Найденное пишется в `config/local.yaml`. Чужие порты перебор сам не открывает: открытие порта может перезагрузить плату на нём (ESP32 — по DTR).
  - «+ Прибор» добавляет прибор в `config/devices.yaml`; во вкладке «Прибор» его окна — имя, подписи каналов, удаление. Файл правится через ruamel.yaml: комментарии и порядок сохраняются.
- Шаг 1.1: настройки. Форма строится из схемы драйвера, шаг можно пропустить. Правки из ⚙ ложатся поверх настроек шаблона, а не заменяют их.
- Подготовка → запись ⇄ пауза → стоп. Стоп возможен только из паузы, на паузе запись продолжается.
- Значок состояния: зелёный — норма, жёлтый — нужно внимание, красный — ошибка.
- График прибора перетаскивается на поле. Брошенный на панель, он накладывается на неё, но не больше двух единиц измерения на панель. С Alt (на телефоне — долгое нажатие) переносится прибор целиком, по панели на единицу измерения.
- Ширина панели: 1 → 2 → вся строка, высота 1 → 2. Раскладка запоминается в браузере отдельно для каждого опыта.
- Панель выносится в отдельное окно браузера. У окна своё подключение к сборщику: оно рисует, даже когда главное свёрнуто. Закрыли окно — панель вернулась. Вместо Dockview: своя сетка уже умеет перетаскивание, наложение и телефон.
- «Сохранить как шаблон» в панели опыта (и сразу после стопа): приборы, их настройки (что отличается от стенда), правила оповещений, раскладка. Опыт по шаблону открывается с его раскладкой.
- Журнал: время заметки берётся по первому нажатию клавиши. Изменения настроек записываются как «было → стало».
- Точки замера на кадре тепловизора становятся каналами. Зоны и полоса профиля задаются в настройках и видны на кадре пунктиром.
- Тексты короткие, пояснения во всплывающих подсказках.
