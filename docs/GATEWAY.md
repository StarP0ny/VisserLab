# МК-шлюз: протокол и железо

> **Этот текстовый черновик заменён бинарным протоколом v1 (7 октября 2026).**
> Актуальная спецификация, подключения и согласованные решения:
> [SensorsMotherboard/docs/PROTOCOL.md](../../SensorsMotherboard/docs/PROTOCOL.md).
> Первый этап: CH32V303CBT6, USB CDC / UART, TCA9548A, SCD41 и SHT41.
> Код ПК: `visserlab/gwproto.py`, `visserlab/drivers/vgw.py`.
> SDP810 и автономный flash-журнал — следующий этап. Ниже исторический черновик.

Черновик для обсуждения, шаг 5 плана. Датчики на I²C (SCD41, SHT45, SDP810) и на 1-Wire (DS18B20) сидят на микроконтроллере, МК отдаёт их отсчёты в ПК. На ПК шлюз — прибор группы `gateway`, датчики — его дети (`child`). Ядро это уже умеет: так работают симуляторы в `tests/stand`.

Главные решения:

- Протокол текстовый, строками с CRC-16. Транспорт — любой поток байт: USB CDC или UART 115200.
- МК только опрашивает датчики по расписанию и шлёт отсчёты целыми числами с меткой своего времени. Пересчёт, привязка к часам ПК, запись, оповещения — на ПК.
- Плата up от терморегуляторов годится после доработки, но в ней нет USB и мало питания. От сети её питать нельзя, если она подключена к ПК: подробности в разделе 1.

## 1. Железо

### Плата up (da up 2 CG 1224, CH32V203G6U6)

Что показала схема:

| Что нужно шлюзу | Вывод | На плате сейчас |
|---|---|---|
| USB D−/D+ | PA11 / PA12 | сегмент B* и разряд Dig1 индикатора: USB нет |
| USART1 TX/RX | PA9 / PA10 | сегменты G*, B* |
| USART2 TX/RX | PA2 / PA3 | входы IN_2 / IN_1 (разъёмы XN2 / XN1) |
| I2C1 SCL/SDA | PB6 / PB7 | разряд Dig6 / управление реле UPR2 |
| свободные для программного I²C | PA1 / PA0 | входы IN_3 / IN_4 (XN6 / XN7), подтяжка 5,1 кОм к VDDA уже есть |
| кварц | PD0 / PD1 | заняты (UPR1, …): только HSI, ±1–2 % |

Все 28 выводов заняты: индикатор, кнопки, реле, четыре аналоговых входа, SWD. Шлюзу подходят только входы IN_1…IN_4: два под UART до ПК, два под I²C.

Входы отличаются RC-фильтром в зависимости от исполнения:

| Вход | da, li, bor | 2ch | bon |
|---|---|---|---|
| IN_1 (PA3, RX) | 51 Ом / 470 пФ ✓ | 51 Ом / 470 пФ ✓ | 51 Ом / 470 пФ ✓ |
| IN_2 (PA2, TX) | 3,3 кОм / 100 нФ ✗ | 3,3 кОм / 100 нФ ✗ | 51 Ом / 470 пФ ✓ |
| IN_3 (PA1, SCL) | 51 Ом / 470 пФ ✓ | 3,3 кОм / 100 нФ ✗ | 3,3 кОм / 100 нФ ✗ |
| IN_4 (PA0, SDA) | 51 Ом / 470 пФ ✓ | 51 Ом / 470 пФ ✓ | без подтяжки, 100 кОм / 100 нФ ✗ |

Фильтр 3,3 кОм / 100 нФ (τ = 330 мкс) не пропустит ни UART, ни I²C. Меньше всего доработки у da/li/bor: R6 3,3 кОм → 51 Ом, C8 100 нФ → 470 пФ, и вход IN_2 становится TX. I²C на 5,1 кОм и 470 пФ пойдёт на 20–50 кГц: датчикам Sensirion этого хватает.

Плата реле при этом не нужна и даже мешает: на одном из входов у неё стоит NTC TH1 на землю (датчик перегрева). Поэтому берём только плату up, провода паяем на площадки XN.

### Питание и безопасность

- **Блоки питания da bp неизолированные.** PN8015 понижает выпрямленную сеть, а мост на плате реле соединён с GND. Значит, земля схемы находится под потенциалом сети. Если подключить плату к ПК через USB-UART, пока она питается от 230 В, земля ПК через мост окажется на сети. Плату up питаем снаружи: 3,3 В от LDO на 5 В USB, на площадки +3V3/GND. Можно и от 24 В лабораторника на +24V, но без L/N.
- **Штатного 3,3 В мало для датчиков.** MC34063 с Rsc 4,7 Ом ограничивает ток ключа примерно 65 мА, это ~30 мА на выходе. SCD41 в момент измерения берёт до ~200 мА. Датчикам нужно своё питание 3,3 В (LDO на 300–500 мА), земля общая, у SCD41 конденсатор 100 мкФ.
- **Провода I²C.** До 1–2 м на 20–50 кГц работает. Если дальше (гофра, мешок), нужен буфер I²C (P82B715, PCA9615) или датчик на отдельной плате со своим МК.

### Вариант B: плата с USB

Готовая плата CH32V203C8T6 с USB-C (WeAct и аналоги, ~300 ₽):

- USB CDC прямо в ПК: без переходника и без доработки;
- два аппаратных I²C (PB6/PB7 и PB10/PB11), поэтому два SHT45 с одним адресом на разных шинах;
- USART1 свободен для датчиков с UART (MH-Z19C, модули O₂);
- 3,3 В от USB через LDO на ~300 мА, кварц 8 МГц, 64 КБ flash и 20 КБ RAM;
- `wch_low_level_drivers`, SOSO, Debug те же. USB CDC берётся из WCH EVT (пример SimulateCDC).

Протокол для A и B одинаковый.

## 2. Кадр

- Строка ASCII не длиннее 120 байт, в конце `\n` (`\r` игнорируется).
- Поля разделяются пробелом; параметры вида `ключ=значение`, значения без пробелов.
- В конце строки ` *XXXX`: CRC-16/CCITT-FALSE (полином 0x1021, начальное значение 0xFFFF) по всем байтам до пробела перед `*`, четыре шестнадцатеричные цифры. Проверка: для строки `123456789` получается `29B1`.
- Строку без CRC или с неверным CRC приёмник выбрасывает и увеличивает счётчик ошибок.

Почему текст, а не двоичный кадр:

- поток читается любым терминалом (`python -m serial.tools.miniterm COM5 115200`);
- МК собирает строку через `sprintf` с целыми числами, без float;
- поток небольшой: SDP810 на 50 Гц — около 2 КБ/с при 11,5 КБ/с у UART 115200.

## 3. Сообщения

Датчик обозначается как `тип@шина:адрес`: `scd41@1:62`, `sht45@1:44`, `sht45@2:44`, `sdp810@1:25`, `ds18b20@w:28FF1C…` (1-Wire, ROM-код). Имя не меняется при перезагрузке, по нему ПК сопоставляет датчик с прибором стенда.

### МК → ПК

| Строка | Когда | Поля |
|---|---|---|
| `HI fw=vgw/0.1 hw=up2cg uid=… up=…` | при старте и на `?` | прошивка, плата, UID 96 бит (0x1FFFF7E8), мс с запуска |
| `D <t> <датчик> k=v …` | отсчёт | `t` — мс МК на момент чтения; значения целые, масштаб задаёт тип датчика |
| `E <t> <датчик> err=<код>` | ошибка датчика | `nack`, `crc`, `timeout`, `busy`, `lost` (после 3 ошибок подряд) |
| `HB <t> rx=<n> drop=<n>` | раз в секунду | битые строки на приёме, выброшенные отсчёты |
| `OK <id> …` / `NO <id> err=<код>` | ответ на команду | |

### ПК → МК

`КОМАНДА <id> …`, где `id` от 1 до 9999: по нему сопоставляется ответ.

| Команда | Что делает |
|---|---|
| `? <id>` | `OK` с полями `HI` |
| `SCAN <id>` | обход шин: `OK <id> dev=scd41@1:62,sht45@1:44,sdp810@1:25` |
| `RUN <id> <датчик> ms=1000` | опрашивать с периодом; повторный `RUN` меняет период |
| `STOP <id> <датчик\|*>` | перестать опрашивать |
| `SET <id> <датчик> k=v` | настройка датчика (раздел 4) |
| `TIME <id>` | `OK <id> t=<мс>` |
| `RESET <id>` | перезапуск после `OK` |

Пример:

```
→ ? 1 *….
← OK 1 fw=vgw/0.1 hw=up2cg uid=3A1F…C2 up=5210 *….
→ SCAN 2 *….
← OK 2 dev=scd41@1:62,sht45@1:44,sdp810@1:25 *….
→ RUN 3 sht45@1:44 ms=1000 *….
← OK 3 *….
← D 6231 sht45@1:44 t=2341 rh=4520 *….
← HB 7000 rx=0 drop=0 *….
← E 7231 sht45@1:44 err=nack *….
```

Если МК перезапустился, он сам присылает `HI` с маленьким `up`. ПК заново отдаёт `RUN` и `SET` и пишет в журнал «шлюз перезапустился».

## 4. Датчики: что делает МК

Идентификация при `SCAN`: ответ по известному адресу и проверочная команда (серийный номер, product id), чтобы не спутать датчики.

| Датчик | Адрес | Как опрашивать | Поля `D` | `SET` |
|---|---|---|---|---|
| SCD41 | 0x62 | `start_periodic` 0x21B1 (раз в 5 с), `data_ready` 0xE4B8, `read` 0xEC05; `ms` не меньше 5000 | `co2` ppm, `t`, `rh` ×100 | `asc=0\|1` (0x2416; нужен `stop` 0x3F86 и 500 мс), `alt=<м>` (0x2427), `hpa=<гПа>` (0xE000, можно на ходу) |
| SHT45 | 0x44 (AD1B) / 0x45 (BD1B) | 0xFD, чтение через 8,3 мс | `t`, `rh` ×100 | `heat=200_1s` … (0x39 и др.): подсушить после конденсата |
| SDP810-500Pa | 0x25 | непрерывно 0x3615 (перепад давления, усреднение до чтения); чтение 9 байт: перепад, T, масштаб 60 Па⁻¹ | `dp` Па ×100, `t` ×100 | `mode=dp\|mf` (0x3615 / 0x3603) |
| DS18B20 | 1-Wire | модуль SensorTemperature, 750 мс на преобразование | `t` ×100 | — |

У всех датчиков Sensirion CRC-8 (полином 0x31, начальное 0xFF) на каждые два байта. Отсчёт с плохим CRC не отправляется, вместо него уходит `E … err=crc`.

## 5. Время

- `t` — время МК в мс, uint32, переполняется через 49 дней. Переполнение учитывает ПК.
- Время отсчёта на ПК: время приёма строки минус (`t` последней строки в пачке − `t` этой строки). К часам ПК привязываемся по самой свежей строке, а интервалы между отсчётами берём из МК. Уход HSI на ±1–2 % даёт 1–2 мс ошибки на 100 мс, этого достаточно.
- Если 3 секунды нет ни одной строки (`HB` идёт раз в секунду), связи нет. Если нет только `D` конкретного датчика, у него статус «нет данных».

## 6. Сторона ПК (VisserLab)

| Что | Где |
|---|---|
| кадр, CRC, разбор, сопоставление ответов по `id` (Future) | `visserlab/gwproto.py`, работает без железа |
| шлюз (`gateway`) | `visserlab/drivers/vgw.py` |
| дети (`child`): `scd41`, `sht45`, `sdp810`, `ds18b20` | там же: каналы, масштаб, настройки → `SET` |
| эмулятор МК на Python | `tests/stand/vgw_emul.py`, тем же протоколом через `socket://`; заменит `sim_mk` |

**Шлюз:**
- **Настройки:** порт (для варианта B — «авто» по USB VID:PID и UID), скорость.
- **discover:** `?` и `SCAN`; дети, которые ответили, считаются найденными.
- **open:** `?`, затем для детей в опыте `RUN` и `SET`.
- **run:** читает строки. `D` уходит в `ctx.emit(…, dev=ребёнок)`, `E` меняет статус ребёнка, `HB` подтверждает, что связь жива.
- **apply** (изменение на ходу) → `SET`; **close** → `STOP *`.

**Ребёнок:**
- **Настройки:** `sensor: sht45@1:44`, период, свои параметры (`asc`, `heat`, `mode`).
- **Действия:** например, «ноль» у SDP810. Считается на ПК: среднее за 5 секунд без потока становится смещением.

**Интерфейс:** «Поиск» по `SCAN` показывает датчики, которых нет в стенде, и предлагает их добавить. Это продолжение «+ Прибор», только для детей шлюза.

**Ядро:** одна доработка — `ctx.online(ok, reason, dev=ребёнок)`, чтобы шлюз мог менять статус отдельного датчика.

## 7. Сторона МК

- **Транспорт.** Вариант A: USART2 с приёмом по DMA в кольцевой буфер (UART и DMA есть в `wch_low_level_drivers`). Вариант B: USB CDC.
- **Строки.** Кольцо приёма на 256 байт, сборка строки до 120, CRC-16 (есть модуль CRC), таблица команд.
- **Отправка.** Очередь строк на 1–2 КБ. При переполнении выбрасываются строки `D`, а не ответы, счётчик потерь уходит в `HB`.
- **I²C.** Вариант B — аппаратный; вариант A — программный, с растяжкой такта и таймаутом. Если SDA зависла, шина восстанавливается девятью тактами SCL.
- **Реестр датчиков.** До 8 штук: тип, шина, адрес, период, время следующего опроса, состояние автомата (команда → ожидание → чтение), счётчик ошибок. Никаких `delay`: ожидания SHT45 (8,3 мс) и SCD41 (1 мс) внутри автомата.
- **SOSO.** На 1 кГц — автоматы датчиков и приём, на 1 Гц — `HB`.
- **Прочее:** IWDG; UID в `HI`. Для варианта A — индикатор: «GW» и число датчиков, «E01» при ошибке.
- **Объём.** Протокол ~3–4 КБ flash, каждый датчик ~1 КБ, USB CDC ~6–8 КБ, RAM ~3 КБ. Вариант A влезает в G6 (32 / 10 КБ), вариант B в C8 (64 / 20 КБ) — с запасом.

## 8. Открытые вопросы

1. Плата: A (up с доработкой, UART через CP210x) или B (CH32V203C8T6 с USB)?
2. Сколько будет SHT45 и какие у них адреса (AD1B — 0x44, BD1B — 0x45): одна шина или две?
3. Длина проводов до датчиков: если больше 1–2 м, нужен буфер I²C.
4. Будут ли датчики с UART (MH-Z19C, O₂)? Для них нужен второй UART, а он есть только в варианте B.
