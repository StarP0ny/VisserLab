# Сборщик

Отдельный процесс, который держит приборы, пишет опыты и обслуживает клиентов: веб-интерфейс, `ctl`, скрипты. Запускает его человек:

```
python -m visserlab collect
```

Ctrl-C в окне сборщика останавливает его. Идущий опыт при этом ставится на паузу и сохраняется. Остановить сборщик по сети нельзя. Если сборщика нет, веб-интерфейс только сообщает об этом и сам его не запускает.

## Состояния

```
IDLE ──prepare──▶ PREP ──start──▶ REC ⇄ PAUSE ──stop──▶ IDLE
                  PREP ──cancel──▶ IDLE
```

- **PREP.** Приборы открыты, данные идут клиентам, на диск ничего не пишется. Последние `preroll_s` секунд хранятся в памяти как предзапись; кадры в ней прорежены до `preroll_fps`.
- **start.** Создаётся папка опыта, в неё сбрасываются предзапись и журнал подготовки.
- **Пауза.** Запись продолжается, отрезок отмечается в журнале и в `meta.yaml`.
- **stop** возможен только из паузы. Это проверяет сборщик, а не интерфейс.
- Опыт всегда один.

## Протокол

TCP `127.0.0.1:8765` (порт задаётся в `config/devices.yaml`), JSON по одной строке в UTF-8 в обе стороны.

```
→ {"id": 7, "cmd": "set", "args": {"device": "pt100", "changes": {"period": "2"}, "by": "телефон"}}
← {"type": "reply", "id": 7, "ok": true, "result": {"changed": {"period": ["1", "2"]}}}
← {"type": "reply", "id": 8, "ok": false, "error": "Стоп — только из паузы"}
```

`by` — кто выполнил действие. Попадает в журнал.

### Команды

| Команда | Аргументы | Когда |
|---|---|---|
| `hello` | `frames` — присылать ли кадры (по умолчанию нет) | всегда; ответ — снимок всего состояния |
| `discover` | `settings` {id: {…}} — правки из интерфейса поверх конфига | не во время перебора; одна проверка каждого прибора |
| `scan` | `devices` [id] (по умолчанию все ненайденные с перебором), `port` — другой порт, только для одного прибора, `settings` | IDLE; перебор в фоне, прогресс — сообщениями `scan` |
| `scan_stop` | — | остановить перебор |
| `ports` | — | последовательные порты системы и какие приборы на них настроены |
| `prepare` | `name`, `devices` [id], `template`, `settings` {id: {…}}, `note`, `alarms` [правила] | IDLE, не во время перебора |
| `start` · `pause` · `resume` · `stop` · `cancel` | — | по автомату выше |
| `note` | `text`, `t` — время первого нажатия клавиши; пустой текст ставит метку | PREP, REC, PAUSE |
| `mark` | — | то же |
| `set` | `device`, `changes` | то же; поля без `live` во время записи запрещены |
| `action` | `device`, `name`, `args` | то же; `reconnect` есть у всех приборов |
| `history` | `channel`, `t_from`, `t_to`, `points` | скаляры текущего опыта, мин/макс в каждом бакете |
| `runs` | `limit` | всегда; опыты на диске, новые сверху |
| `drivers` | — | драйверы, которые можно добавить: схема настроек и умолчания |
| `device_add` | `driver`, `name`, `settings`, `channels` {ключ: подпись}, `id` | IDLE, не во время перебора; пишет в `devices.yaml` |
| `device_edit` | `id`, `name`, `channels` {ключ: подпись; пустая — убрать} | то же |
| `device_del` | `id` | то же; шлюз — вместе с детьми |
| `template_save` | `name`, `layout` [{`series`, `w`, `h`}], `overwrite` | идёт опыт или только что остановлен; если шаблон есть, а `overwrite` нет — ответ `exists: true` |

Снимок `hello` содержит: `state`, `session` (имя, t0, паузы, папка, правила оповещений, шаблон), `devices` (статус, настройки, схема формы, каналы), `inventory` (все приборы конфига, результат поиска, `scan` — что перебирает драйвер, `local` — что найдено перебором, `channels` с подписями), `templates` (с раскладкой), `alarms`, `events` (журнал с начала подготовки), `last` (последние значения), `scan` (состояние перебора).

### Сообщения сборщика

| `type` | Когда | Содержимое |
|---|---|---|
| `state` | смена состояния | `state`, `name`, `t0`, `pauses`, `dir`, `last_run` |
| `status` | раз в секунду | `elapsed`, статусы приборов и возраст отсчёта, `alarms` (`level`: ok/warn/crit, `items`), `last` |
| `data` | 10 раз в секунду | `ch`: {канал: [[t, v], …]}, не больше 4 точек: края и экстремумы |
| `frame` | не чаще `frame_push_fps`, только если `hello` был с `frames: true` | `ch`, `t`, `format` (`raw` или `jpeg`), `dtype`, `shape`, `b64` |
| `event` | запись в журнал | `event`: `t`, `kind`, `text`, `by`, … |
| `device` | у прибора изменился набор каналов | `device` — как в `hello` |
| `device_status` | смена статуса прибора | `id`, `status` (wait/ok/stale/lost), `reason` |
| `found` | после `discover` и неудачного перебора | результаты поиска |
| `scan` | перебор: старт, прогресс не чаще 10 раз в секунду, итог | `run`, `ids`, `cur`, `frac` (0…1 по текущему прибору), `text`, `done` {id: {`ok`, `note`, `settings`}} |
| `inventory` | перебор нашёл прибор; стенд поправили | `inventory`, `found` |
| `templates` | сохранили шаблон | `templates` |
| `lag` | клиент не успевал читать, часть живых данных выброшена | нужно заново запросить `hello` |

Виды записей журнала (`kind`): `user` — заметка, `mark` — метка, `state` — старт/пауза/стоп, `set` — настройки и действия, `manual` — ручной отсчёт, `sys` — служебное, `warn`, `crit` — оповещения.

Канал обозначается как `прибор:ключ`, например `pt100:T1` или `thermal:frame`.

## Приборы и драйверы

Драйвер — это класс в `visserlab/drivers/`, зарегистрированный через `@register`. Контракт описан в [visserlab/core/driver.py](../visserlab/core/driver.py): схема настроек, каналы, `discover`, `open` / `run` / `close`, `apply` для настроек с `live`, `action` и список `actions`, которые интерфейс может предложить.

Драйверы вне пакета подключаются списком `plugins` в `devices.yaml`: пути к `.py` относительно папки конфига. Так подключены симуляторы в `tests/stand`.

### Поиск

- `discover(cfg)` — одна проверка на заданных настройках. Её зовёт «Обновить».
- `scan(cfg, report, stop, taken)` и `scan_what` — перебор параметров подключения, начиная с `cfg`. `report(frac, text)` — прогресс, `stop` — отмена, `taken` — настройки остальных приборов: чужой адрес на той же шине не считается находкой. Возвращает найденные настройки или `None`.
- Поле с типом `port` интерфейс показывает списком портов системы.

Найденное перебором сборщик сразу применяет и пишет в `local.yaml` рядом с `devices.yaml`, только то, что отличается. `local.yaml` перекрывает `settings` из `devices.yaml` и в git не идёт.

PTA8D08 отвечает на адрес 255 при любом своём адресе и называет его в регистре 0xFD. Поэтому перебор сначала пробует на каждой скорости адрес из настроек и 255 (≈ 1 с), и только если ответы сталкиваются (несколько плат на шине) — все адреса 1–247 (до ~2,5 мин).

Канал сообщает интерфейсу всё, что нужно для показа: `kind`, `unit`, `rate`, `dp`, для кадров — `shape`, `dtype`, пересчёт сырого значения в физическое (`scale`, `offset`), для точки замера — где она на кадре (`at`: ключ кадра, x, y; для зоны — ещё w, h), для профиля — ось (`axis`). Точки с экрана удаляются правым кликом, зоны — только в настройках.

| group | Поток | Откуда данные |
|---|---|---|
| `direct` | свой | своё подключение |
| `gateway` | свой | от имени детей: `ctx.emit(..., dev=child)` |
| `child` | нет | даёт шлюз |
| `manual` | нет | действие `add` |
| `calc` | нет | `inputs()` → `compute()` |

Если шлюз теряет связь, все его дети получают статус `lost` с общей причиной, а оповещение поднимается одно.

Если прибор бросил исключение, он получает статус `lost`, и сборщик переоткрывает его каждые 2 с. Если данных нет дольше 3 периодов (но не меньше 2 с), статус становится `stale` и поднимается жёлтое оповещение.

## Оповещения

Правила задаются в шаблоне опыта:

```yaml
alarms:
  - {channel: "pt100:T1", op: ">", value: 130, clear: 128, hold: 3, level: warn, text: "Корпус на входе > 130 °C"}
```

`hold` — сколько секунд условие должно держаться, прежде чем поднимется оповещение. `clear` — порог возврата в норму. `level`: `warn` — жёлтое, `crit` — красное. Потеря связи всегда `crit`.

## Опыт на диске

```
runs/<YYYY-MM-DD_HHMMSS>_<имя>/
  meta.yaml                       приборы, настройки, каналы, файлы, правила оповещений; при стопе — итоги и паузы
  events.jsonl                    журнал
  <прибор>.csv                    t_unix и скалярные каналы, строка на отсчёт
  <прибор>.<канал>.bin            кадры и профили подряд, сырые байты; dtype и shape — в meta.yaml
  <прибор>.<канал>.index.csv      t_unix и номер кадра
  <прибор>.<канал>/000001.jpg     видео, плюс index.csv
```

Если набор каналов прибора меняется посреди опыта (например, добавили точку замера), начинается новый сегмент: `<прибор>.2.csv`. Все файлы только дописываются и сбрасываются на диск раз в секунду.

Кадр тепловизора весит 256×192×2 байта = 96 КБ. При 5 к/с это ≈ 1,8 ГБ в час, при 25 к/с — ≈ 8,8 ГБ.
